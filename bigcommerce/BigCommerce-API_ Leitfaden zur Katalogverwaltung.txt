Hier ist eine granulare How-to-Dokumentation für die Verwaltung des BigCommerce-Katalogs, basierend auf den bereitgestellten Quellen. Diese Anleitung deckt die Authentifizierung sowie die Verwaltung von Marken, Kategorien (Category Trees), Produkten und Produktmodifikatoren ab.
1. Vorraussetzungen & Authentifizierung
Bevor Sie API-Anfragen stellen können, müssen Sie sicherstellen, dass jede Anfrage authentifiziert ist.
* Header: Fügen Sie jeder Anfrage den Header X-Auth-Token hinzu 1.
* Content-Type: Für POST- und PUT-Anfragen sollte der Header Content-Type: application/json und Accept: application/json gesetzt sein 2.
* Basis-URL: Die Anfragen erfolgen an https://api.bigcommerce.com/stores/{store_hash}/v3/catalog/... 1.
2. Marken verwalten (Brands)
Die Marken-Endpunkte ermöglichen das Erstellen, Aktualisieren und Löschen von Marken.
Schritt 1: Eine Marke erstellenSenden Sie eine POST-Anfrage an /catalog/brands.
* Erforderliche Felder: Das Feld name ist zwingend erforderlich und muss eindeutig sein 2, 3.
* Optionale Felder: Sie können page_title, meta_keywords, meta_description und image_url hinzufügen 3, 4.
* Limit: Ein Shop kann maximal 30.000 Marken enthalten 2.
Schritt 2: Marken abrufenSenden Sie eine GET-Anfrage an /catalog/brands.
* Sie können nach id, name, oder page_title filtern 5, 6.
* Verwenden Sie include_fields, um nur bestimmte Daten abzurufen, oder exclude_fields, um Daten auszuschließen 6.
Schritt 3: Eine Marke aktualisierenSenden Sie eine PUT-Anfrage an /catalog/brands/{brand_id}.
* Um ein Markenbild zu aktualisieren, senden Sie eine Anfrage mit einer neuen image_url 7.
Schritt 4: Marken löschenSenden Sie eine DELETE-Anfrage an /catalog/brands.
* Wichtig: Um Marken zu löschen, müssen Sie zwingend einen name-Filter in der Query angeben (z. B. ?name=MarkenName) 8.
3. Kategorien verwalten (Category Trees)
Hinweis: Die alten "Categories V3"-Endpunkte gelten als veraltet (deprecated). Es wird empfohlen, stattdessen die "Category Trees"-Endpunkte zu verwenden, da diese sowohl Multi-Storefront (MSF) als auch Single-Storefront unterstützen 9, 10.
Schritt 1: Kategoriebäume abrufenSenden Sie eine GET-Anfrage an /catalog/trees.
* Dies gibt eine Liste aller Kategoriebäume zurück. Sie können nach channel_id filtern 11.
Schritt 2: Kategorien erstellen oder aktualisieren (Upsert)Senden Sie eine PUT-Anfrage an /catalog/trees.
* Dieser Endpunkt kann Bäume sowohl erstellen als auch aktualisieren 12.
* Erstellung: Wenn kein id-Feld übergeben wird, wird ein neuer Baum erstellt. Hierbei ist das Feld name sowie die channels-ID erforderlich (ein Baum kann nur einem Kanal zugewiesen werden) 13.
* Aktualisierung: Wenn ein Objekt eine id enthält, wird es als Update verarbeitet. Das Feld channels darf bei einem Update nicht enthalten sein 13.
Schritt 3: Kategoriebäume löschenSenden Sie eine DELETE-Anfrage an /catalog/trees.
* Sie müssen einen Filter verwenden, z. B. id:in mit einer kommagetrennten Liste von IDs 14.
4. Produkte verwalten (Products)
Die Produkt-API ermöglicht das Erstellen einzelner Produkte sowie Batch-Updates.
Schritt 1: Ein Produkt erstellenSenden Sie eine POST-Anfrage an /catalog/products.
* Erforderliche Felder: name, type (Werte: physical oder digital), weight, price und categories (Letzteres ist erforderlich, wenn die V2-Produkterfahrung im Control Panel aktiviert ist) 15, 16, 17.
* Details:
* name: Muss eindeutig sein, max. 250 Zeichen 16.
* weight: Min. 0, max. 9.999.999.999 17.
* categories: Ein Array von IDs (max. 1.000 IDs) 18.
* Es kann nur ein Produkt pro Anfrage erstellt werden, aber Varianten können über das variants-Array direkt mit erstellt werden 19.
Schritt 2: Produkte abrufenSenden Sie eine GET-Anfrage an /catalog/products.
* Sie können Filter wie id:in, sku, price, is_visible oder keyword verwenden 20, 21.
* Mit dem Parameter include können Sub-Ressourcen wie images, variants oder custom_fields direkt mitgeladen werden 20.
Schritt 3: Ein einzelnes Produkt aktualisierenSenden Sie eine PUT-Anfrage an /catalog/products/{product_id}.
* Fast alle Felder, die beim Erstellen genutzt werden, können hier aktualisiert werden 22.
Schritt 4: Mehrere Produkte aktualisieren (Batch)Senden Sie eine PUT-Anfrage an /catalog/products.
* Senden Sie ein Array von Produktobjekten. Jedes Objekt muss die id des Produkts enthalten 23.
* Das Limit liegt bei 10 Produkten pro Batch-Anfrage 23.
Schritt 5: Produkte löschenSenden Sie eine DELETE-Anfrage an /catalog/products.
* Um versehentliches Löschen aller Produkte zu verhindern, muss ein Filter (z. B. id:in=1,2,3) angegeben werden 24.
* Maximal 250 Produkte können gleichzeitig gelöscht werden 24.
5. Produktmodifikatoren verwalten (Modifiers)
Modifikatoren erlauben Kunden, Produkte anzupassen (z. B. Gravur, Farbe), ändern aber nicht den Lagerbestand 25.
Schritt 1: Einen Modifikator erstellenSenden Sie eine POST-Anfrage an /catalog/products/{product_id}/modifiers.
* Erforderliche Felder: required (Boolean), display_name und type 26.
* Typen: Zulässige Werte für type sind u. a. date, checkbox, file, text, dropdown, swatch 27.
* Konfiguration: Abhängig vom Typ müssen Sie das option_values-Array (für Auswahlmöglichkeiten) oder das config-Objekt (z. B. für Textbeschränkungen) nutzen 28, 29.
* Hinweis: Bei Checkbox-Modifikatoren müssen Optionswerte in einem separaten Schritt nach der Erstellung aktualisiert werden 26.
Schritt 2: Modifikatoren abrufenSenden Sie eine GET-Anfrage an /catalog/products/{product_id}/modifiers.
* Gibt eine Liste aller Modifikatoren für das spezifische Produkt zurück 30.
Schritt 3: Einen Modifikator aktualisierenSenden Sie eine PUT-Anfrage an /catalog/products/{product_id}/modifiers/{modifier_id}.
* Hier können Eigenschaften wie display_name oder required geändert werden 31.
Zusammenfassung wichtiger Regeln
1. Grenzwerte: Achten Sie auf Limits, z. B. 10 Produkte pro Batch-Update 23 oder 250 beim Löschen 24.
2. Validierung: Stellen Sie sicher, dass Pflichtfelder wie name und price bei der Produkterstellung vorhanden sind, um 422-Fehler zu vermeiden 32.
3. Veraltete Endpunkte: Nutzen Sie für Kategorien bevorzugt /catalog/trees anstelle der alten /catalog/categories-Endpunkte 10.
