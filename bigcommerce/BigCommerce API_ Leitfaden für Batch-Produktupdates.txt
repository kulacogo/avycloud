Um große Katalogänderungen über die API durchzuführen, nutzen Sie die Batch-Update-Funktionen. Da die BigCommerce API für Batch-Updates spezifische Limits pro Anfrage hat, müssen Sie Ihre Daten in kleinere Pakete ("Chunks") unterteilen und diese nacheinander senden.
Hier ist der granulare Prozess für die Nutzung der Batch-Update-Funktion für Produkte:
1. Grundlagen des Produkt-Batch-Updates
Verwenden Sie den Endpunkt PUT /catalog/products, um mehrere Produkte gleichzeitig zu aktualisieren.
* Endpoint: PUT https://api.bigcommerce.com/stores/{store_hash}/v3/catalog/products 1.
* Limitierung: Ein Batch ist auf 10 Produkte pro Anfrage begrenzt 2. Für große Katalogänderungen müssen Sie Ihre Datensätze also in Gruppen von maximal 10 Objekten aufteilen und für jede Gruppe einen eigenen API-Aufruf tätigen.
* Payload: Der Body der Anfrage muss ein Array von Produktobjekten sein 3.
2. Struktur der Anfrage (Request)
Damit das Update erfolgreich ist, müssen bestimmte Felder beachtet werden:
* Pflichtfeld: Die id des Produkts ist für Batch-Updates zwingend erforderlich 2, 3. Ohne die ID kann das System das Produkt nicht zuordnen.
* Schreibgeschützte Felder: Versuchen Sie nicht, Felder wie date_created, date_modified, calculated_price oder base_variant_id zu ändern, da diese "Read-Only" sind 2.
* Beispiel-Update: Wenn Sie nur den Preis und den Lagerbestand ändern wollen, senden Sie nur die id, price und inventory_level im Objekt.
3. Mögliche Änderungen
Sie können fast alle Produktattribute im Batch aktualisieren. Zu den häufigsten gehören:
* Preise: price, cost_price, retail_price, sale_price 4.
* Lagerbestand: inventory_level (sofern inventory_tracking auf product gesetzt ist) 5, 6.
* Kategorien: Das Feld categories erwartet ein Array von IDs. Wichtig: Wenn Sie dieses Array senden, werden alle bestehenden Kategorien des Produkts überschrieben 7.
* Versand: weight, width, height, depth, fixed_cost_shipping_price 8, 9.
* Sichtbarkeit: is_visible (true/false) 9.
4. Antwortverarbeitung & Fehlerbehandlung
Die API gibt möglicherweise einen "Multi-Status" zurück. Das bedeutet, dass innerhalb eines Batches einige Updates erfolgreich sein können, während andere fehlschlagen.
* Status: Eine Antwort deutet oft darauf hin, dass ein "Partial Failure" aufgetreten ist 10.
* Beispiel: Produkt A wurde erfolgreich aktualisiert, aber bei Produkt B fehlte eine Validierung (z. B. negativer Lagerbestand).
* Vorgehensweise: Überprüfen Sie die Antwort auf das errors-Objekt, um spezifische Probleme bei einzelnen Items zu identifizieren 11. Wenn URL-Updates fehlschlagen, prüfen Sie auf ungültige Zeichen oder Duplikate 12.
5. Weitere Batch-Funktionen für den Katalog
Neben Produkten gibt es weitere Endpunkte für Massenänderungen:
* Kategorien (Category Trees): Nutzen Sie PUT /catalog/trees, um Kategoriebäume per "Upsert" zu bearbeiten 13.
* Wenn ein Objekt eine id enthält, wird es als Update behandelt.
* Ohne id wird eine neue Kategorie erstellt (hierbei ist name Pflicht) 14.
* Varianten: Es gibt spezifische Endpunkte für Update Variants (Batch) 15, 16, um Varianteninformationen effizienter zu aktualisieren als über das Hauptprodukt-Objekt.
* Preise (Bulk Pricing): Nutzen Sie die Bulk Pricing Rules-Endpunkte für mengenbasierte Preisregeln 17.
