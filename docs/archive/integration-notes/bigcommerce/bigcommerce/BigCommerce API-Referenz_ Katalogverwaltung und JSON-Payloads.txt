Hier sind die passenden Code-Snippets (JSON-Payloads) für die zuvor beschriebenen Funktionen der BigCommerce API. Diese Beispiele zeigen die Struktur des Request Body für die jeweiligen Endpunkte. ### 1. Marken (Brands) Erstellen einer Marke (POST /catalog/brands) Das Feld name ist das einzige Pflichtfeld. Sie können jedoch Bilder und SEO-Daten direkt mitgeben 1, 2, 3. json { "name": "Exklusive Marke", "page_title": "Exklusive Marke - Offizieller Shop", "meta_keywords": ["Luxus", "Mode", "2024"], "meta_description": "Die beste Mode von Exklusive Marke.", "image_url": "https://cdn.beispiel.com/images/marke_logo.png", "search_keywords": "Luxus, Kleidung" }  Aktualisieren einer Marke (PUT /catalog/brands/{brand_id}) Senden Sie nur die Felder, die geändert werden sollen 4. json { "page_title": "Exklusive Marke - Summer Sale", "image_url": "https://cdn.beispiel.com/images/neues_logo.png" }  --- ### 2. Kategoriebäume (Category Trees) Der Endpunkt /catalog/trees nutzt die Methode PUT für Upsert-Operationen (Erstellen und Aktualisieren in einem). Erstellen einer neuen Kategorie (PUT /catalog/trees) Wenn Sie keine id angeben, wird eine neue Kategorie erstellt. Das Array channels ist hierbei Pflicht 5. json [ { "name": "Herrenschuhe", "parent_id": 0, "channels": [6], "is_visible": true } ]  Aktualisieren einer Kategorie (PUT /catalog/trees) Wenn Sie eine id angeben, wird die Kategorie aktualisiert. Wichtig: Das Feld channels darf bei einem Update nicht enthalten sein 5. json [ { "id": 105, "name": "Herrenschuhe & Stiefel", "parent_id": 20, "description": "Beste Qualität für den Winter" } ]  --- ### 3. Produkte (Products) Erstellen eines einzelnen Produkts (POST /catalog/products) Pflichtfelder sind name, type, weight und price. Varianten können direkt im variants-Array definiert werden 7, 8. ```json { "name": "Premium T-Shirt", "type": "physical", "weight": 0.5, "price": 29.99, "cost_price": 10.00, "categories": 9, 10, "inventory_tracking": "variant", "is_visible": true, "description": "
Ein hochwertiges T-Shirt aus Baumwolle.
", "variants": [ { "sku": "TSHIRT-S", "price": 29.99, "option_values": { "option_display_name": "Größe", "label": "Small" } } ] }  **Batch-Update mehrerer Produkte (`PUT /catalog/products`)** Sie müssen ein Array von Objekten senden, wobei jedes Objekt die `id` enthalten muss [11]. json { "id": 101, "price": 24.99, "inventory_level": 100 }, { "id": 102, "is_visible": false, "sale_price": 19.99 }  --- ### 4. Produktmodifikatoren (Modifiers) Modifikatoren werden pro Produkt über `POST /catalog/products/{product_id}/modifiers` erstellt. **Beispiel A: Textfeld (für Gravuren)** Hier wird das `config`-Objekt genutzt, um Einschränkungen wie die Maximallänge zu definieren [12]. json { "type": "text", "required": false, "display_name": "Gravur Text", "sort_order": 1, "config": { "default_value": "", "text_max_length": 20, "text_characters_limited": true } }  **Beispiel B: Dropdown-Liste (Auswahloptionen)** Hier wird das `option_values`-Array genutzt, um die Auswahlmöglichkeiten zu definieren. Adjusters (Preisanpassungen) können ebenfalls eingefügt werden [13], [12]. json { "type": "dropdown", "required": true, "display_name": "Material", "sort_order": 2, "option_values": { "label": "Gold", "sort_order": 1, "is_default": false, "adjusters": { "price": { "adjuster": "relative", "adjuster_value": 50.00 } } }, { "label": "Silber", "sort_order": 2, "is_default": true, "adjusters": { "price": null } } } ```
